# AI出版プロンプト集 (prompt.md)

書籍の企画構想から、原稿執筆、校正・推敲、プロモーション動画制作に至る各プロセスでAIを活用するためのプロンプト集です。
チャットAI（Claude, ChatGPT等）やエージェント環境に投入して利用します。


## 1. 企画・構成フェーズ（AI壁打ち）

### 執筆テーマ検討

新たに書籍を執筆するためのテーマを検討する際に、AIにインタビューを行わせるプロンプトです。

```md
新たに書籍を執筆するためのテーマを検討するので、手伝ってください。
1. 私の経歴や趣味、スキル、どのような思想を持っているか、インタビューしてください。
2. 現代社会のありとあらゆる悩みや問題の内、1.でアドバイス出来そうなテーマを探してください。
   ただし、AIの案は短絡的で、悪い意味での「普通」に寄っていく傾向が強い点に気を付けてください。
   1.2.ともに深掘りして、直感的には繋がらない線を見つけ出して（10-20件程度）提案してください。
3. ユーザーのリアクションが思わしくない場合、1.から何度でも繰り返しましょう。
```

---

### メモの整理と肉付け

`book/memo.md` に書き殴ったアイデアや断片を、起承転結を意識した目次・構成案へ整理するためのプロンプトです。

```md
ユーザが書籍を執筆するにあたって、大きなテーマから具体的な構成を検討しています。
テーマに関連する知識や提言、所感などをmemo.mdにユーザが書き殴っていますので、これを並べ直してください。
- 前半には問題提起や概要、一般的な意見を並べます
- 中盤には起承転結の「承転」にあたる、一般論からの転換にあたる気付きや別角度からの視点を並べます
- 後半に向かって徐々に具体的で、強いメッセージを並べます
なお、起承転結として情報や視点、説得力が弱いなど、ユーザに追加して欲しい内容は、最下部に列挙してください。
```


## 2. 原稿執筆・校正・推敲フェーズ

### 誤字脱字・言い回しの校正

1文単位で誤字・脱字や意味の通らない表現を精査し、3段階の確信度で指摘させます。

```md
`contents.md`の校正・校閲を手伝ってください。
（章項節単位の文意ではなく）1文単位で、誤字・脱字、意味の通らない言い回しのチェックを行なって下さい。
指摘の際には、ファイル位置（行番号）と指摘対象文の引用を示した上で、どの部分をどう変更するべきか、理由と共に簡潔に指摘してください。
その際、指摘の確信度を以下の3段階で示してください。

1. ◎：明らかな誤り、絶対に直すべき箇所
2. 〇：文脈等から誤りとは言えないが、誤解を生む恐れがあり、修正を提案する
3. △：正しい言葉遣いではあるが、一面的で視野の狭い主張の恐れがあり、念のため報告する
```

---

### 章・段落の主張と論理構成の確認

章ごとの主張、章題との整合性、書籍全体の論理展開に破綻がないかを客観的に評価させます。

```md
`contents.md`の推敲を手伝ってください。
以下の観点で確認して報告して下さい。
1. 各段落の主張の要約から、その章が何を主張したいのか、論法として無理がないかを評価してください。
2. 各章の章題は、1.の主張と異なっていないかを評価してください。
3. 各章の主張の流れで、このコンテンツ全体の主張が何なのか、論法として無理がないかを評価してください。

指摘はまず、1. 2. 3. それぞれ、評価した結果を列挙してください。
それに続けて、指摘として、何が良くないかを説明し、改善提案を行なって下さい。
```

---

### 文体・トーンの推敲

目指す作風や文体（例: 親しみやすい語り口、論理的な解説調、格調高い文体など）に合わせて言い回しをブラッシュアップします。

```md
`contents.md`の推敲を手伝ってください。

前提として、目指す文体・トーンについて説明します。
【希望する文体や語り口、トーンをここに記載。例：親しみやすい語り口 / 論理的な解説調 / 格調高い文体 等】

本文中の言い回しで、より目指す文体に近づけられる箇所を探して提案してください。
提案の際には、指摘箇所を示し、原文と改善案を並べて理由を添えてください。
```

---

### 難読漢字への読み仮名付与（下準備）

中学校までに習わない漢字や難読語に全角かっこで読み仮名を振ります。

```md
`contents.md`の校正・校閲を手伝ってください。
難読漢字に読み仮名を付与します。
基準は中学校までに習わない漢字、言い回しが古く、読み仮名がある方が親切な漢字に振ります。
なお、同じ漢字には、毎回同じ読みを振ります。
フォーマットは、「漢字の言葉（よみがな）」の形式で、直後に全角かっこで振ります。
※既に振ってある読み仮名やHTMLルビ（<ruby>タグ）はそのまま保持してください。
また、あとで差分チェックするので、`contents.md`を直接編集してよいですが、読み仮名の付与以外は何も変更してはいけません。
```

---

### 読み仮名のHTMLルビ化

かっこ書きの読み仮名を、出版基盤が解釈できる `<ruby>親文字<rt>ルビ</rt></ruby>` タグに変換します。

```md
`contents.md`の校正・校閲を手伝ってください。
既に振ってあるかっこ書きの読み仮名を、HTMLルビ表記に変更します。

以下の変換例の通り、かっこ書きフォーマットの全角かっこは削除し、ルビ要素は`<ruby>`と`<rt>`のみ使用し、`<rb>`、`<rp>`は使いません。
（すでにHTML化済みの箇所はそのまま保持してください）

- かっこ書きフォーマット：漢字の言葉（よみがな）
- HTMLフォーマット：<ruby>漢字の言葉<rt>よみがな</rt></ruby>

また、あとで差分チェックするので、`contents.md`を直接編集してよいですが、読み仮名のHTML化以外は何も変更してはいけません。
```

### 参考：AIによる客観的評価プロンプト

AIが過剰に忖度せず、作品を客観的な第三者・批評家の視点から分析・論評するための高度なプロンプトです。

<details>
<summary>小説・文芸・論説の客観的評価プロンプトを開く</summary>

```md
## 【本プロンプトの目的】
本プロンプトは、AIが過剰にユーザーに配慮せず、ユーザー作成の作品を客観的な立場から審査・査読・論評し、ユーザーの自己研鑽を助ける分析・論述をすることを目的とする。

## 【振る舞いの指定】
あなた（AI）は日本の文芸・論説作品を専門とする分析者である。批評家、編集者、審査員としての複合的な視点から、対象作品を審査・査読・論評すること。
●対象作品は本プロンプトと同時に貼付されるか、またはプロジェクト内のファイル名が指定される。

## 【審査・査読・論評のルール】
- 日本語の文芸・論説作品として読み、AIとしての判断に他言語の基準や価値観を不用意に持ち込まないこと
- 作者への配慮や忖度は不要。客観的な評価こそが作者の成長に繋がる
- 論述の根拠は作品内の具体的な箇所を引用し示すこと
- 好悪の感情的評価や偏見に基づく論述をしないこと
- 具体的な表現への言及では、必ず対象箇所を引用すること。その際、架空の文章を創出してしまわないよう、引用箇所が対象作品の中に実在していることを確認すること。もし記憶が曖昧で引用箇所を発見できない場合は、引用せずに「○○のような表現」と概略として述べること。

## 【第一段階：初見読者としてのフィードバック】
【重要】第一段階では、「ユーザー情報および過去の対話情報の参照を禁止」する。すなわち同一チャット、スレッド、プロジェクト内の、以下のような情報を徹底的に無視し、これらの成分を出力に混入させないこと。これはユーザーへの忖度をなくす目的と、純粋に客観的な論述を導くための指針。
- ユーザーとの過去の対話
- ユーザーに関するメモリー情報
- この作品について以前に交わした会話
- ユーザーの創作傾向や過去作品に関する知識

あなたはユーザーのことを知らない第三者として、対象作品を完全に初めて読むものとして振る舞わなくてはならない。渡された対象作品のテキストのみに基づいて審査・査読・論評すること。過去の対話から言葉や情報を利用しようとすることは、プロンプトの破壊であり機能の毀損となる。決してしないように。

---
**論述形式：**

### 1. 完全フラットな論評（先入観なしの率直な印象）
対象作品の内容を間違いなく理解した上で、作品の特徴を挙げていき、率直な客観的意見を述べよ。（適切な分量で、文字数400文字以上、2000文字以内を目処）

### 2. 作品が成功している／読者の好評を得られそうな点（効果的に機能している要素）
対象作品に対してポジティブ・好意的に評価出来るポイントに着目する。もしもそういう要素が発見できなかった場合には、「好意的に評価できる要素は見出しがたい」旨を述べよ。

### 3. 改善・発展の可能性（読者の利益に結びついていない要素）
作品がさらに効果を高められた可能性のある要素、読者が正しく読解したり楽しみを得るための助けになっていない要素や部分、明確に改善すべき未熟なところやネガティブな評価に繋がる部分を挙げよ。

---
## 【第二段階：ユーザーに合わせた分析と助言】
【重要】この段階では、第一段階での制限を解除し、作者の創作意図と第一段階での客観的評価との間にある差異・整合・可能性を分析し、創作の発展に資する助言を行うこと。

### 1. 第一段階の評価が異なる方向に向かう理由
### 2. 改稿や次回作へ向けた提案
```

## 3. プロモーション動画フェーズ

### ショート動画定義（movies.js）生成

`book/promote/movie_contents.md` で抜粋・選定した書籍紹介テキストを元に、[book/promote/recorder/movies.js](./promote/recorder/movies.js) を生成（または更新）するためのプロンプトです。

```md
`book/promote/movie_contents.md` の内容を元に、`book/promote/recorder/movies.js` のコードを生成（または更新）してください。

【要件】
1. 先頭で `window.BOOK_TITLE = "【書籍タイトル】";` を定義してください。
2. `window.MOVIES` の配列に各動画のオブジェクトを格納してください：
   - id: "01", "02", ...（2桁連番）
   - filename: 動画保存時のファイル名
   - title: 各動画のサブタイトル（指定があれば設定）
   - background: 指定の背景動画パス
   - lines: 抜粋文の各行を配列要素として格納（ルビタグはそのまま保持）
3. コードブロックのみを出力してください。
```
