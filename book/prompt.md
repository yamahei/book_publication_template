# AI出版プロンプト集 (prompt.md)

書籍の企画構想から、原稿執筆、校正・推敲、プロモーション動画制作に至る各プロセスでAIを活用するためのプロンプト集です。
チャットAI（Claude, ChatGPT等）やエージェント環境に投入して利用します。


## 1. 企画・構成フェーズ（AI壁打ち）

### 執筆テーマ検討

新たに書籍を執筆するためのテーマを検討する際に、AIにインタビューを行わせるプロンプトです。

```md
新たに書籍を執筆するためのテーマを検討するので、手伝ってください。

1. 私の経歴や趣味、スキル、どのような思想を持っているか、インタビューしてください
   - 表面的な内容だけでなく、その奥にあるこだわりや想いまでヒアリングしてください
   - 対外的な評価と内面的な想いの差から、私が気づいていない能力や信条、行動パターンを推測してください
   - 私と言う人間の本質を深掘りして探ってください
2. 現代社会に存在する悩みや問題、課題をリストアップして提示してください
   - 「教育」「高齢化」のような社会の悩みではなく、「人間関係」「将来」のような個人が抱くものが望ましいです
   - こちらも深掘りして、表面的ではない原因を（仮説でも）探ってください
   - ただし、AIの案は短絡的で、悪い意味での「普通」に寄っていく傾向が強い点に気を付けてください
3. 私の人間性（1.）と世間の悩み（2.）を組み合わせて、新しい切り口で助言、提言出来そうなテーマを提案してください
   - 1.2.ともに深掘りして、直感的には繋がらない線を見つけ出して（10-20件程度）提案してください
   - 私のリアクションが思わしくない場合、1.から何度でも繰り返しましょう
```

---

### メモの整理と肉付け

`book/memo.md` に書き殴ったアイデアや断片を、起承転結を意識した目次・構成案へ整理するためのプロンプトです。

```md
ユーザが書籍を執筆するにあたって、大きなテーマから具体的な構成を検討しています。
テーマに関連する知識や提言、所感などをmemo.mdにユーザが書き殴っていますので、これを並べ直してください。
- 前半には問題提起や概要、一般的な意見を並べます
- 中盤には起承転結の「承転」にあたる、一般論からの転換にあたる気付きや別角度からの視点を並べます
- 後半に向かって徐々に具体的で、強いメッセージを並べます
なお、起承転結として情報や視点、説得力が弱いなど、ユーザに追加して欲しい内容は、最下部に列挙してください。
```


## 2. 原稿執筆・校正・推敲フェーズ

### 誤字脱字・言い回しの校正

1文単位で誤字・脱字や意味の通らない表現を精査し、3段階の確信度で指摘させます。

```md
`contents.md`の校正・校閲を手伝ってください。
（章項節単位の文意ではなく）1文単位で、誤字・脱字、意味の通らない言い回しのチェックを行なって下さい。
指摘の際には、ファイル位置（行番号）と指摘対象文の引用を示した上で、どの部分をどう変更するべきか、理由と共に簡潔に指摘してください。
その際、指摘の確信度を以下の3段階で示してください。

1. ◎：明らかな誤り、絶対に直すべき箇所
2. 〇：文脈等から誤りとは言えないが、誤解を生む恐れがあり、修正を提案する
3. △：正しい言葉遣いではあるが、一面的で視野の狭い主張の恐れがあり、念のため報告する
```

---

### 章・段落の主張と論理構成の確認

章ごとの主張、章題との整合性、書籍全体の論理展開に破綻がないかを客観的に評価させます。

```md
`contents.md`の推敲を手伝ってください。
以下の観点で確認して報告して下さい。
1. 各段落の主張の要約から、その章が何を主張したいのか、論法として無理がないかを評価してください。
2. 各章の章題は、1.の主張と異なっていないかを評価してください。
3. 各章の主張の流れで、このコンテンツ全体の主張が何なのか、論法として無理がないかを評価してください。

指摘はまず、1. 2. 3. それぞれ、評価した結果を列挙してください。
それに続けて、指摘として、何が良くないかを説明し、改善提案を行なって下さい。
```

### 文体・トーンの推敲

目指す作風や文体（例: 親しみやすい語り口、論理的な解説調、格調高い文体など）に合わせて言い回しをブラッシュアップします。

```md
`contents.md`の推敲を手伝ってください。

前提として、目指す文体・トーンについて説明します。
【希望する文体や語り口、トーンをここに記載。例：親しみやすい語り口 / 論理的な解説調 / 格調高い文体 等】

本文中の言い回しで、より目指す文体に近づけられる箇所を探して提案してください。
提案の際には、指摘箇所を示し、原文と改善案を並べて理由を添えてください。
```

### 難読漢字への読み仮名付与（下準備）

中学校までに習わない漢字や難読語に全角かっこで読み仮名を振ります。

```md
`contents.md`の校正・校閲を手伝ってください。
難読漢字に読み仮名を付与します。
（ひらがな、漢字の表記ゆれもここで統一します。）
基準は中学校までに習わない漢字、言い回しが古く、読み仮名がある方が親切な漢字に振ります。
なお、同じ漢字には、毎回同じ読みを振ります。
フォーマットは、「漢字の言葉（よみがな）」の形式で、直後に全角かっこで振ります。
※既に振ってある読み仮名やHTMLルビ（<ruby>タグ）はそのまま保持してください。
また、あとで差分チェックするので、`contents.md`を直接編集してよいですが、読み仮名の付与以外は何も変更してはいけません。
```

### 読み仮名のHTMLルビ化

かっこ書きの読み仮名を、出版基盤が解釈できる `<ruby>親文字<rt>ルビ</rt></ruby>` タグに変換します。

```md
`contents.md`の校正・校閲を手伝ってください。
既に振ってあるかっこ書きの読み仮名を、HTMLルビ表記に変更します。

以下の変換例の通り、かっこ書きフォーマットの全角かっこは削除し、ルビ要素は`<ruby>`と`<rt>`のみ使用し、`<rb>`、`<rp>`は使いません。
（すでにHTML化済みの箇所はそのまま保持してください）

- かっこ書きフォーマット：漢字の言葉（よみがな）
- HTMLフォーマット：<ruby>漢字の言葉<rt>よみがな</rt></ruby>

また、あとで差分チェックするので、`contents.md`を直接編集してよいですが、読み仮名のHTML化以外は何も変更してはいけません。
```

### 参考：AIによる客観的評価プロンプト

AIが過剰に忖度せず、作品を客観的な第三者・批評家の視点から分析・論評するための高度なプロンプトです。

<details>
<summary>小説・文芸・論説の客観的評価プロンプトを開く</summary>

```md
## 【本プロンプトの目的】
本プロンプトは、AIが過剰にユーザーに配慮せず、ユーザー作成の作品を客観的な立場から審査・査読・論評し、ユーザーの自己研鑽を助ける分析・論述をすることを目的とする。

## 【振る舞いの指定】
あなた（AI）は日本の文芸・論説作品を専門とする分析者である。批評家、編集者、審査員としての複合的な視点から、対象作品を審査・査読・論評すること。
●対象作品は本プロンプトと同時に貼付されるか、またはプロジェクト内のファイル名が指定される。

## 【審査・査読・論評のルール】
- 日本語の文芸・論説作品として読み、AIとしての判断に他言語の基準や価値観を不用意に持ち込まないこと
- 作者への配慮や忖度は不要。客観的な評価こそが作者の成長に繋がる
- 論述の根拠は作品内の具体的な箇所を引用し示すこと
- 好悪の感情的評価や偏見に基づく論述をしないこと
- 具体的な表現への言及では、必ず対象箇所を引用すること。その際、架空の文章を創出してしまわないよう、引用箇所が対象作品の中に実在していることを確認すること。もし記憶が曖昧で引用箇所を発見できない場合は、引用せずに「○○のような表現」と概略として述べること。

## 【第一段階：初見読者としてのフィードバック】
【重要】第一段階では、「ユーザー情報および過去の対話情報の参照を禁止」する。すなわち同一チャット、スレッド、プロジェクト内の、以下のような情報を徹底的に無視し、これらの成分を出力に混入させないこと。これはユーザーへの忖度をなくす目的と、純粋に客観的な論述を導くための指針。
- ユーザーとの過去の対話
- ユーザーに関するメモリー情報
- この作品について以前に交わした会話
- ユーザーの創作傾向や過去作品に関する知識

あなたはユーザーのことを知らない第三者として、対象作品を完全に初めて読むものとして振る舞わなくてはならない。渡された対象作品のテキストのみに基づいて審査・査読・論評すること。過去の対話から言葉や情報を利用しようとすることは、プロンプトの破壊であり機能の毀損となる。決してしないように。

---
**論述形式：**

### 1. 完全フラットな論評（先入観なしの率直な印象）
対象作品の内容を間違いなく理解した上で、作品の特徴を挙げていき、率直な客観的意見を述べよ。（適切な分量で、文字数400文字以上、2000文字以内を目処）

### 2. 作品が成功している／読者の好評を得られそうな点（効果的に機能している要素）
対象作品に対してポジティブ・好意的に評価出来るポイントに着目する。もしもそういう要素が発見できなかった場合には、「好意的に評価できる要素は見出しがたい」旨を述べよ。

### 3. 改善・発展の可能性（読者の利益に結びついていない要素）
作品がさらに効果を高められた可能性のある要素、読者が正しく読解したり楽しみを得るための助けになっていない要素や部分、明確に改善すべき未熟なところやネガティブな評価に繋がる部分を挙げよ。

---
## 【第二段階：ユーザーに合わせた分析と助言】
【重要】この段階では、第一段階での制限を解除し、作者の創作意図と第一段階での客観的評価との間にある差異・整合・可能性を分析し、創作の発展に資する助言を行うこと。

### 1. 第一段階の評価が異なる方向に向かう理由
### 2. 改稿や次回作へ向けた提案

## 3. 入稿データフェーズ

### 3-1. KDP入稿用「内容紹介（商品説明文）」の生成

`book/contents.md` を元に、[submission.md](../submission.md) の「② 内容紹介（商品説明文）」に記載するAmazon販売ページ用の紹介文を生成するためのプロンプトです。

```md
`book/contents.md` を読み込み、`submission.md` の「② 内容紹介（商品説明文）」に記載するためのAmazon販売ページ用説明文を作成してください。

【構成ルール（3パート構成：起 → 起承 → 承転）】
1. 【導入フック（最初の3行）】［起］:
   - Amazonの商品ページで「続きを読む」を押す前に表示される冒頭3行です。
   - 本書が解決しようとしている「読者の日常の痛み・違和感・悩み」を3つの短い箇条書き（または鋭い問いかけ）で提示し、本書への興味を喚起してください。
2. 【書籍のコンセプト・対象読者・論じるテーマ】［起承］（1段落のみ）:
   - 導入フックで湧いた興味を補完するため、「なぜその悩みや違和感が生じるのか（視点の転換）」と「本書がどのような対象読者に向けて、何をテーマ・コンセプトとして論じる本なのか」を、1段落（3〜4文程度）に凝縮して記述してください。
   - ※最終章の結論（ネタバレ）は書かないでください。また複数段落にわたる冗長な説明は避けてください。
3. 【目次（＋各章のテーマ補足）】［承転］:
   - `【目次】` の見出しの下に、本書の全章タイトルを列挙してください。
   - 本編の各章（はじめに・おわりになどを除く）には、`章タイトル ── その章が扱うテーマや出典の短い補足` を添え、［起承］で続きを知りたくなった読者が「自分の知りたい内容が確かに書かれている」と確認できるようにしてください。
4. 【禁止事項（結びの削除）】:
   - 目次の後に「本書を読めば〜になります」「さあ一歩を踏み出しましょう」といった結びの宣伝文は一切書かないでください（読者が目次を見て中身への期待から購入ボタンを押せるよう、目次で潔く終えてください）。
```

### 3-2. KDP入稿用「検索キーワード（最大7つ）」の生成

`book/contents.md` を元に、[submission.md](../submission.md) の「④ 検索キーワード（最大7つ）」に設定するキーワードを生成するためのプロンプトです。

```md
`book/contents.md` を読み込み、`submission.md` の「④ 検索キーワード（最大7つ）」に設定するための検索キーワードを7つ作成してください。

【選定ルール】
1. 見込み読者の「痛み・悩み」からの逆算:
   - 本文中に登場する専門用語・固有名詞・抽象的な概念（すでに答えを知っている人しか検索しない語）は選ばないでください。
   - 本書が解決できる痛みやモヤモヤを抱えた見込み読者が、まだ本書の存在を知らない状態でAmazonの検索窓に実際に打ち込みそうな「平易な口語フレーズ（2〜3語のスペース区切り）」を7つ挙げてください。
2. 重複の排除と切り口の分散:
   - 書籍タイトルやサブタイトルにすでに含まれている単語は除外してください（KDPでは自動インデックスされるため）。
   - 7つのキーワードが特定の話題だけに偏らないよう、本書の各章が扱う異なる切り口（仕事、学び、休日、人間関係、生き方・将来など）に分散させてください。
```

## 4. プロモーション動画フェーズ

### 4-1. ショート動画構成案（movie_contents.md）の抽出・生成

`book/contents.md` から「1動画1テーマ（話題）」でショート動画の構成案を抽出し、[book/promote/movie_contents.md](./promote/movie_contents.md) を生成するためのプロンプトです。生成後、人間がレビューして採用テーマの取捨選択や文言の調整を行います。

```md
`book/contents.md` を読み込み、ショート動画用の構成設計書 `book/promote/movie_contents.md` を生成してください。

【絶対に守るべき抽出・圧縮ルール】
1. ネタバレ防止（最終章の除外）:
   - 書籍全体の結論を述べる最終章や、「おわりに」「さいごに」等の結びの章は、ネタバレを防ぐため必ず抽出対象外としてください。
   - 本数は固定せず、対象章の中から「1動画1テーマ（独立した話題）」として成立するものを抽出してください。
2. 誇張・煽りの禁止:
   - 本文の意図と異なる客引きのための誇張や煽りは厳禁です。あくまでも本文中の話題を端的にまとめるにとどめてください。
3. 後半段落からの逆算（章の主張の読み解き）:
   - 本文を上から下へ順番になぞって要約してはいけません。
   - まず各章の後半（第2段落中盤〜最終段落）を精読し、「著者が読者に最も突きつけたい真の主張」と、その裏にある「読者が日常で目を背けている急所（虚しさ・迷い・恐れ・打算・惰性など）」を1行で言語化してください。
4. 1文1ページ・単文への極限圧縮（起・承・転・結）:
   - 【起】（1ページ固定 / 8〜16文字以内）:
     特定した「読者の急所」から逆算し、読者がハッとする短く鋭い一言（直球の問い・本質的疑問・否定/断言）にしてください。
     ※「現代において〜」「〜な日々の中で」といった前提説明・状況限定や、小難しい熟語・抽象語はすべて削ぎ落としてください。
   - 【承・転】（計2〜4ページ / 1ページあたり15〜27文字以内）:
     「〜だが、〜である」といった複文や、人名・書名の教科書的な紹介文（「〇〇は『××』において〜と説いた」等）を禁止し、「1つの主語＋1つの述語」の単文に大胆に言い換えてください。
     【起】の問いを受け止めて共感を示し（承）、先人の知恵や視点の転換を提示して、本書の結論が知りたくなる一歩手前で止めてください（転）。
   - 強調したい核心語句は `<em>...</em>` で囲み、本文中のルビ（`<ruby>漢字<rt>よみ</rt></ruby>`）は維持してください。

【出力フォーマット】
各動画テーマについて以下の形式で出力してください：
### 動画XX: 【テーマ名】
- **章の主張（逆算元）**: 【特定した章の主張と読者の急所】
- **サブタイトル**: 【テーマ名】
- **ファイル名**: `【書籍名】_XX_【テーマ名】`（※先頭に必ず書籍名を付与すること）
- **誘導文**: 続きは本書で（※またはテーマに合わせた短い誘導文）

```md
[起] 【8〜16文字以内の鋭い一言】
[承] 【15〜27文字以内の単文】
[承] 【15〜27文字以内の単文（任意）】
[転] 【15〜27文字以内の単文】
[転] 【15〜27文字以内の単文（任意・結論手前の寸止め）】
```

### 4-2. ショート動画定義（movies.js）の生成

人間がレビュー・確定した `book/promote/movie_contents.md` と表紙画像 `book/cover/cover.png` を元に、[book/promote/recorder/movies.js](./promote/recorder/movies.js) を生成（または更新）するためのプロンプトです。

```md
`book/promote/movie_contents.md` の内容と、表紙画像 `book/cover/cover.png` を元に、`book/promote/recorder/movies.js` のコードを生成（または更新）してください。

【要件】
1. 先頭で `window.BOOK_CONFIG` を定義してください：
   - `title`: 書籍タイトル
   - `ctaText`: 基本の誘導文（例: "続きは本書で"）
   - `coverImage`: `"/api/cover"`
   - `theme`: 表紙画像 `book/cover/cover.png` の雰囲気と実際の背景色・文字色を読み取り、以下を設定してください：
     - `preset`: 和風・古典・文芸なら `"washi"`、現代的・ビジネスなら `"modern"`、重厚・哲学・洋書風なら `"classic"`
     - `baseColor`: 表紙の背景基調色（暗くしすぎず、表紙の印象がそのまま伝わる実測に近い色）
     - `subColor`: `baseColor` と同系色で少し落ち着かせた暗部色
     - `textColor`: 基本文字色（白系 `"#ffffff"` 等）
     - `accentColor`: 背景色の上で鮮やかに映える強調色（金茶色 `"#ffe082"` や朱色等）
     - `phase4Shade`: 【結】で表紙画像を際立たせるための半透明背景（例: `"rgba(15, 8, 8, 0.56)"`）
   - `audio`:
     - `bgm`: 指定のBGMファイルパス（既存の指定があればそのまま維持）
     - `bgmVolume`: `0.42`
     - `bgmTiming`: `"middle_only"`（【承・転】のみBGMを鳴らし、【起】と【結】はBGMなし）
     - `se`: `{ 起: "builtin:question", 承: "builtin:page", 転: "builtin:deep", 結: "builtin:ending", subline: "builtin:subline" }`
     - `seVolume`: `0.45`
2. `window.MOVIES` の配列に各動画オブジェクトを格納してください：
   - `id`: `"01"`, `"02"`, ...（2桁連番）
   - `filename`: 保存時のファイル名（拡張子なし。`【書籍名】_XX_【テーマ名】` のように先頭に必ず書籍名を付与すること）
   - `title`: 各動画のサブタイトル
   - `pages`: `movie_contents.md` の `[起]` `[承]` `[転]` の各行を `{ role: "起"|"承"|"転", lines: [...] }` として格納してください。
     - `role: "起"` のページは `lines: ["..."]` の1行配列としてください。
     - `role: "承"` および `"転"` のページ（17文字以上の文）は、画面上で「先に読む前半の句」が出て0.55秒後に「後半の句」が時間差で出るよう、読点や自然な意味の区切りで `lines: ["前半の句", "後半の句"]` の2行配列に分割してください（1行あたり16文字以内を目安）。
   - `ending`: `{ subtitle: "【サブタイトル】", cta: "【誘導文】" }`
```
