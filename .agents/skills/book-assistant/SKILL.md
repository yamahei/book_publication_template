# 書籍制作・推敲アシスタントスキル

本スキルは、`book/prompt.md` に定義されたプロンプト体系に基づき、書籍制作の各フェーズにおいて高品質な執筆支援・推敲・校正を実行するための指示書です。

---

## 1. 企画・構成フェーズ（AI壁打ち）

### A. 執筆テーマ検討
ユーザーが新たな書籍のテーマを検討したい場合の指示手順：
1. **インタビュー（人間性の深掘り）**: ユーザーの経歴、趣味、スキル、どのような思想を持っているかを質問して引き出す。
   - 表面的な内容だけでなく、その奥にあるこだわりや想いまでヒアリングする。
   - 対外的な評価と内面的な想いの差から、ユーザー自身が気づいていない能力や信条、行動パターンを推測する。
   - ユーザーという人間の本質を深掘りして探る。
2. **現代の悩み・課題のリストアップ**: 現代社会に存在する悩みや問題、課題をリストアップして提示する。
   - 「教育」「高齢化」のような社会の悩みではなく、「人間関係」「将来」のような個人が抱くものを対象とする。
   - こちらも深掘りして、表面的ではない原因を（仮説でも）探る。
   - ※AIの案は短絡的で、悪い意味での「普通」に寄っていく傾向が強い点に注意する。
3. **課題とのマッチング・テーマ提案**: ユーザーの人間性（1.）と世間の悩み（2.）を組み合わせて、新しい切り口で助言・提言できそうなテーマを提案する。
   - 1.と2.をともに深掘りし、直感的には繋がらない線を見つけ出して10〜20件程度提案する。
   - ユーザーのリアクションが思わしくない場合は、1.から何度でも繰り返す。

### B. メモの整理と肉付け
ユーザーが `book/memo.md` に書き殴ったアイデアや断片を、起承転結を意識した目次・構成案へ整理する場合の手順：
- **前半**: 問題提起、概要、一般的な意見を並べる。
- **中盤**: 起承転結の「承転」にあたる、一般論からの転換・気付き・別角度からの視点を並べる。
- **後半**: 具体性を持たせ、強いメッセージ・結論を並べる。
- **不足情報の提示**: 起承転結として説得力や情報が弱い箇所があれば、最下部に「追加してほしい内容リスト」を提示する。

## 2. 原稿執筆・校正フェーズ

### A. 誤字脱字・言い回しの校正
`book/contents.md` の校正・校閲を行う場合の手順：
- 1文単位で誤字・脱字、意味の通らない言い回しを精査する。
- 指摘時は「ファイル位置（行番号）」「指摘対象文の引用」「変更案」「理由」を明記する。
- 各指摘に以下の確信度を必ず付与する：
  - **◎**: 明らかな誤り、絶対に直すべき箇所
  - **〇**: 文脈等から誤りとは言えないが、誤解を生む恐れがあり、修正を提案する箇所
  - **△**: 正しい言葉遣いではあるが、一面的で視野の狭い主張の恐れがあり、念のため報告する箇所

### B. 章・段落の主張と論理構成の確認
`book/contents.md` の推敲・論理チェックを行う場合の手順：
1. 各段落の主張の要約から、その章が何を主張したいのか、論法として無理がないかを評価。
2. 各章の章題が、1.の主張と齟齬がないかを評価。
3. 各章の主張の流れから、書籍全体の結論・メッセージとして論法に飛躍や破綻がないかを評価。
- 出力はまず 1, 2, 3 の評価結果を列挙し、続いて具体的な改善提案を提示する。

### C. 文体・トーンの推敲
ユーザーが指定する作風・語り口（例: 親しみやすい語り口、論理的な解説調、古風・硬派な文体など）に合わせて言い回しを改善提案する。
- 指摘箇所を示し、原文と改善案を並べて理由を添える。

### D. 難読漢字の読み仮名付与・HTMLルビ化
- **付与基準**: 中学校までに習わない漢字、言い回しが古く読み仮名がある方が親切な漢字。
- **同一性**: 同一作品内では、同じ漢字には一貫して同じ読みを振る。
- **HTMLルビ書式**: `<ruby>親文字<rt>ルビ</rt></ruby>`（`<rb>` や `<rp>` は使用しない）。

## 3. 入稿データフェーズ

`submission.md` に記載するAmazon KDP販売ページ用のデータを生成する場合の手順：

### A. KDP入稿用「内容紹介（商品説明文）」の生成（3パート構成）
1. **【起】導入フック（最初の3行）**: 読者の日常の痛み・違和感を3つの短い箇条書き（または問いかけ）で提示し興味を喚起する。
2. **【起承】書籍のコンセプト・対象読者・論じるテーマ（1段落のみ）**: フックで湧いた興味を補完するため、なぜその痛みが生じるのか、どのような対象読者に向けて何を論じる本なのかを **1段落（3〜4文程度）** に凝縮する（最終章のネタバレは避ける）。
3. **【承転】目次（＋各章のテーマ補足）**: `【目次】` の下に全章タイトルを列挙し、本編各章には扱うテーマや出典の短い補足を添える。
4. **結びの削除**: 目次の後に冗長な結びや宣伝文は一切書かず、目次で潔く終える。

### B. KDP入稿用「検索キーワード（最大7つ）」の生成
- 本文中の専門用語・固有名詞や、書籍タイトル・サブタイトルに含まれる語は除外する。
- 本書が解決できる痛みを持つ見込み読者が検索窓に実際に打ち込みそうな「平易な口語フレーズ（2〜3語のスペース区切り）」を、異なる切り口（学び、仕事、休日、人間関係、生き方など）に分散させて7つ作成する。

## 4. プロモーション動画フェーズ

ショート動画の制作依頼を受けた際は、一気に `movies.js` まで生成せず、必ず以下の **第1段階（構成案の作成と人間レビュー）** と **第2段階（動画定義の生成）** に分けて進めること。

### A. 第1段階：ショート動画構成案の抽出・生成（`book/contents.md` → `book/promote/movie_contents.md`）
1. **最終章・結びの除外（ネタバレ防止）**:
   - 書籍全体の結論を述べる最終章や「おわりに」「さいごに」等の結びの章は、必ず抽出対象外とする。
   - 本数は決め打ちせず、対象章の中から「1動画1テーマ（話題）」として成立するものを抽出する。
2. **誇張・煽りの厳禁**:
   - 本文の意図と異なる客引きのための誇張や煽りは絶対に行わない。
3. **後半段落からの逆算（章の主張の読み解き）**:
   - 本文を上から下へ順になぞって要約してはならない。
   - 各章の後半（第2段落中盤〜最終段落）を精読し、「著者の真の主張」と、その裏にある「読者の急所（虚しさ・迷い・恐れ・打算・惰性など）」をまず1行で特定する。
4. **1文1ページ・単文への極限圧縮**:
   - **【起】（1ページ固定 / 8〜16文字以内）**: 特定した「読者の急所」から逆算し、前提説明（「現代において〜」等）や硬い熟語をすべて削ぎ落とした、素朴で鋭い一言（直球の問い・本質的疑問・否定/断言）にする。
   - **【承・転】（計2〜4ページ / 各15〜27文字以内）**: 複文や人名・書名の教科書的な紹介を禁止し、「1つの主語＋1つの述語」の単文に大胆に言い換える。【起】を受け止めて共感を示し（承）、先人の知恵や視点の転換を提示して結論の一歩手前で止める（転）。
   - 核心語句は `<em>...</em>` で囲み、ルビ（`<ruby>親文字<rt>ルビ</rt></ruby>`）は保持する。
   - **ファイル名規則**: 各動画のファイル名は `【書籍名】_XX_【テーマ名】` のように先頭に必ず書籍名を付与する。
5. **人間レビューの実施**:
   - `book/promote/movie_contents.md` に出力したら、ユーザーに内容（テーマの取捨選択・文言）のレビューを依頼し、合意を得てから第2段階へ進む。

### B. 第2段階：ショート動画定義の生成（`movie_contents.md` ＋ `cover.png` → `book/promote/recorder/movies.js`）
1. **表紙画像（`book/cover/cover.png`）の色味・雰囲気の踏襲**:
   - `book/cover/cover.png` を確認（必要に応じて画像のRGB値を計測）し、`window.BOOK_CONFIG.theme` に適切な `preset`（`"washi"` / `"modern"` / `"classic"`）および表紙の印象を再現する明るい基調色 `baseColor`、同系暗部色 `subColor`、文字色 `textColor`、強調色 `accentColor`、フェーズ4の50%透過背景 `phase4Shade` を設定する。
2. **音響・タイミング設定（`BOOK_CONFIG.audio` / `timing`）**:
   - `bgmTiming` はデフォルトで `"middle_only"`（【承・転】のみBGM再生、【起】と【結】はBGMなし）、`seVolume` は `0.45` とする（既存のBGMパス等があれば維持する）。
3. **ファイル名と時間差表示用の2行分割（`window.MOVIES`）**:
   - `filename` は `【書籍名】_XX_【テーマ名】`（先頭に必ず書籍名を付与、拡張子なし）とする。
   - 各動画の `pages` 配列において、`role: "起"` は1行配列 `lines: ["..."]` とし、`role: "承"` および `"転"`（17文字以上の文）は、画面上で「先に読む前半の句」が出て0.55秒後に「後半の句」が出るよう、読点や自然な意味の区切りで `lines: ["前半の句", "後半の句"]` の2行配列（1行あたり16文字以内目安）に分割して出力する。

### C. プロモーション動画用「SNS説明文（＋ハッシュタグ5つ）」の生成（`book/promote/README.md` 用）
- ①読者の痛みを突く1〜2行の導入、②本書のコンセプト（1段落）＋主要テーマ抜粋（3〜4項目の箇条書き）＋書籍案内、③文末に検索キーワードから抜粋した見込み読者向けハッシュタグ5つ（`#...`）を配置する。
